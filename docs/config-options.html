📊 分析报告

依据"UI 字段 → CLI 拼装"的真实代码链路做的判定。

✅ 工作良好 / 可用

  • Network 页最干净：所有字段都正确映射到 buildYtDlpArgs，代理/模板/格式/并发/嵌入均生效。
  • Bilibili 主体：快速模式、解析接口、画质/编码优先级、各 --skip-*、--work-dir 均有对应 CLI。
  • Media 主路径：remux/transcode/audio/extract/thumbnail/gif/frames 在 buildFfmpegArgs 都有完整实现。
  • Music 的合并逻辑：顶部字段会被 buildConfigs 合并进 JSON，参数错误被 parseObject 捕获并显示。
  • Settings 两项：真实存储并被各页面读取。

🔁 多页面共通的选项

  • 输出目录Bilibili · Network · Media · Music — 共享 Settings 的 defaultOutputDirectory。
  • 代理服务器Network · Music — 形态不同：Network 是 --proxy；Music 合并进每个源的 requests.proxies。
  • Cookie / 登录态Bilibili · Network · Music — Bilibili 用文本 Cookie + Access Token + 扫码；Network 用浏览器 Cookie；Music 用多行 Cookie。
  • 快速模式卡片全部 4 个功能页 — 统一的 mode-card / operation-tabs。
  • 高级参数折叠Bilibili · Network · Music — advanced-toggle + advanced-panel。
  • TemplateManagerBilibili · Network · Media · Music — 按 featureKey 保存/恢复。
  • DirectoryInput5 个页面 — 统一目录选择组件。

⚠️ 存在问题（行为有歧义 / 静默改写 / 校验缺失）

  • Bilibili 三个"默认已开启"开关无法关闭： multiThread / forceHttp / forceReplaceHost。代码只在 === true 时 push flag，未提供 --no-* 反向 flag。开关默认 false（不加 flag = 走 BBDown 默认 = 开启），打开只是显式再开一次。用户无法通过 UI 关闭这三项。
  • Media: audioCodec=copy 被静默改写：audio 操作下若有音频滤镜/采样率/声道数，会静默切到 aac；容器也会强制归一化（m4a→aac、ogg→opus）。UI 无提示。
  • Media: videoCodec=copy 在有视频滤镜时静默改写为 videoEncoderFallback（videotoolbox→amf→nvenc→qsv→mpeg4）。
  • Media: audioBitrate 在多数操作中被忽略：仅当 resolvedAudioCodec 非 null 且非 copy 时才追加。video-extract / subtitle-extract / thumbnail / gif / frames 不会用到，但 UI 不总是隐藏。
  • Network: audioFormat/subtitleLanguages 是"模式条件"参数但长期可见：默认值 best、zh.*,en.* 易让人误以为"始终下载中英字幕"。
  • Music: 数值上限无校验：searchSize(max=100)、threadCount(max=50) 只做 Math.max(1,…)，没有上限钳制。
  • Music: 四个高级 JSON 是裸文本：默认 {}，语法错误会抛错显示，但无 schema/字段提示。
  • Bilibili: encodingPriority 无 placeholder/示例：相比 qualityPriority 少了示例，填写门槛高。

🗑️ 无效 / 冗余 / 体验差

  • multiThread / forceHttp / forceReplaceHostBilibili — 功能性无效：见上节，开关无法关闭对应行为。
  • videoEncoderFallback 链Media — 首项 h264_videotoolbox 仅 macOS 存在；Windows 上若 libx264 也缺失，会回退到不可用编码器。fallback 链没按平台过滤。
  • audioCodec 下拉"自动选择兼容编码"(=copy)Media — 文案与实际语义不一致（实际是"原样复制；遇到滤镜再静默改 aac"）。
  • audioBitrate 默认 192kMedia — 在以视频为主的操作里几乎不生效，但仍带默认值。
  • audioFormat=bestNetwork — 非 audio 模式完全不生效，默认值易引起误解。
  • accessTokenBilibili — 仅 TV/APP/BiliPlus 接口所需，但 api=web（默认）时填了也不生效，无联动禁用。
  • host / epHost / area（BiliPlus 三件套）Bilibili — 仅自建反代时才有意义，对 99% 用户属冗余，建议折叠到二级。
  • 四个高级 JSONMusic — 终端用户门槛过高，musicdl 上游文档有限，易写了不生效。

🚫 无配置项的页面（仅展示 / 管理）

  • HomePage — 依赖检测、版本来源 pill、Lite 安装命令，全部只读。
  • TasksPage — 任务状态、取消、导出日志，无配置。
  • LicensesPage — 纯静态许可信息。

🎯 建议优先修复（Top 3）

  • 1. Bilibili 的 multiThread/forceHttp/forceReplaceHost：补 --no-* 反向开关，或从 UI 移除。
  • 2. Media 在静默改写 videoCodec/audioCodec 时给出 UI 提示，或锁定不可选项。
  • 3. Network 的 audioFormat / subtitleLanguages 按模式条件禁用，避免误判为"全局生效"。
